# Google login: исследование текущего сайта

Проверено 9 ноября 2026 года. Работающая авторизация бота не менялась.

## Что подтверждено

1. Кнопка Google в опубликованном клиенте сайта выполняет переход на
   `https://api.teswirler.com/auth/google`.
2. Анонимный GET этого адреса возвращает HTTP 302 на
   `https://accounts.google.com/o/oauth2/v2/auth` со следующими параметрами:
   - `response_type=code`;
   - `redirect_uri=https://api.teswirler.com/auth/google/callback`;
   - `scope=email profile`.
3. На сайте существует клиентская страница `https://teswirler.com/auth/callback`.
   Её код вызывает `refreshAccessToken()`, затем `loginWithTokens(accessToken)`
   и переводит пользователя на главную страницу. Обмен refresh-cookie выполняется
   через `/auth/refresh` с `credentials: include` и `X-Auth-Transport: cookie`.
4. Вход через Google не сводится к отправке Google ID token прямо в наш бот:
   текущий опубликованный интерфейс использует серверный redirect flow сайта.

Публичный код, исследованный в этой проверке:

- `/_next/static/chunks/381zbpzzkl0_k.js` — кнопка и общий клиент авторизации;
- `/_next/static/chunks/3h6rg86du4uu1.js` — завершающая страница входа.

В двух проверенных анонимных ответах 302 не было параметра `state`, PKCE challenge
или заголовка Set-Cookie. Это наблюдение начального ответа, а не полный аудит
проверок сервера. Для новой привязки к Telegram обязательно нужна защита от подмены
и повторного использования запроса авторизации.

## Что пока не проверено

- Интерактивный вход в Google и успешный серверный callback не выполнялись.
- Исходный код backend Teswirler пока не получен. Точные атрибуты выдаваемой
  Google-входом refresh-cookie, проверка OAuth state и логика создания/объединения
  аккаунтов неизвестны.
- Редирект успешного backend callback на клиентскую страницу `/auth/callback`
  следует из архитектуры опубликованного клиента, но не наблюдался после реального
  успешного входа.

## Рекомендуемая интеграция с ботом

Оставить существующий Google OAuth на доменах сайта и добавить выдачу одноразового
разрешения на подключение Telegram. Пароль Google и токены доступа к почте боту
не требуются.

1. Бот создаёт случайный запрос подключения, связанный с Telegram user ID,
   с коротким сроком действия. В ссылке передаётся непрозрачный идентификатор,
   а не доверенный на слово `chat_id`.
2. Пользователь открывает страницу подключения на teswirler.com в системном
   браузере и входит через имеющуюся кнопку Google.
3. Сайт показывает, какой аккаунт подключается к какому Telegram-пользователю,
   и запрашивает подтверждение. Запрос подключения сохраняется через OAuth
   перенаправления с проверяемым state/серверной сессией.
4. После подтверждения сайт выдаёт короткоживущий одноразовый код и ссылку
   возврата в бота. Код должен быть связан с исходным запросом и Telegram user ID.
5. Бот обменивает код на сессию Teswirler через защищённый server-to-server API,
   проверяет `/auth/me` и сохраняет сессию существующим шифрованием Fernet.
   Обмен кода атомарно помечает его использованным.

На стороне сайта понадобятся страница подключения и API создания/погашения
разрешений. В боте — выбор способа входа, обработка кода и существующая процедура
подключения с начальной загрузкой истории и проверкой уникальности аккаунта.

Сервер бота может оставаться доступным только в локальной сети: он сам
обращается к HTTPS API сайта. Google redirect URI остаётся на сервере сайта.
Не следует считать ID token, выпущенный для отдельного OAuth-клиента бота,
автоматически пригодным для авторизации на Teswirler.

## Документация Google

- [Web server OAuth flow](https://developers.google.com/identity/protocols/oauth2/web-server):
  redirect URI должен соответствовать зарегистрированному клиенту; state связывает
  ответ с исходным запросом.
- [Ограничения встроенного браузера](https://developers.google.com/identity/protocols/oauth2/web-server):
  Google может отклонять вход во встроенных user-agent. В интерфейсе следует
  предусмотреть открытие системного браузера.
- [Проверка Google ID token](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token):
  audience должен соответствовать разрешённому OAuth client ID.
